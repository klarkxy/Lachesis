## 结论

浏览器使用隔离数据、实际应用/API/数据库与受控假执行器，没有调用模型或供应商凭据。实际操作验证：

1. 共享供应商容量为 2 时显示 2/4，占用外的工单明确等待供应商容量。
2. 容量调到 4 后显示 4/4，第五张就绪工单等待全局容量。
3. 暂停不终止已运行工单，也不继续派发。
4. 取消一张工单仅停止该 Run，生成一个检查点，未生成 Delivery；显式继续后在暂停状态中排队，其他三个 Run 保持运行。
5. 未运行工单的可写范围、只读范围和依赖可保存，状态随依赖变为 blocked。

浏览器临时页面和测试服务已关闭。真实无模型 Windows 探针返回 `sandbox_write_grant_failed`，确认这项失败诊断来自实际 dsh 环境；不把确定性替身测试视为原生执行成功证据。

## 保留边界与重跑前条件

- **Windows 环境兼容性未解决。** 当前执行令牌下的 dsh 写授权仍被拒绝。后续必须在拟运行服务的实际身份和目录下通过真实 readiness，再进行模型施工。此次未降低沙箱保护或改动系统 ACL。
- **历史崩溃不自动解锁。** 没有持久化执行范围退出证明的旧 Run 保持 `recovery_required`；仅重启服务不是退出证明。已确认退出的失败或取消 Run 可以使用本次交付的检查点接续。
- **演练仍需重新设计。** 原编号串行依赖和逐张等待的驱动未在此次变更中重跑或替换。重跑前应按实际代码依赖划分可并行工单，再验证真实模型的并发区间和最终组合成果。
- **原运行数据未修改。** 原数据库 `.lachesis/reading-ledger-real-run/data/lachesis.sqlite` 保持 46 个 Run；最后事件为序号 9694、`application.updated`、`2026-09-24T12:08:13.923Z`。没有用新服务启动或迁移该数据库。
