# 为什么要做 Lachesis？

日期：2026-10-02  
状态：核心定位文档

---

## 一句话定位

> **企业级、自托管的多 harness 工单调度系统**

---

## 和云 Agent 的核心区别

Lachesis 不是「又一个云 agent」，而是针对**企业内网、团队协作、成本敏感、需要审计**场景的解决方案。

### 对比表

| 维度 | Devin / Replit Agent | Cursor / Claude Code | Lachesis |
|------|---------------------|---------------------|----------|
| **部署方式** | 云服务 | 本地客户端 | **自托管**（你的机器/内网）|
| **代码位置** | 上传到第三方云 | 本地 | **完全可控** |
| **隐私控制** | 第三方持有 | 本地（但代码可能发给模型 API）| **完全可控**（内网部署 + 自选模型）|
| **Harness** | 固定 | 固定 | **可插拔**（dsh/codex/claude/自定义）|
| **模型选择** | 有限选择 | 有限选择 | **任意模型**（自己的 API key）|
| **并发数** | 单任务 | 单任务 | **可配置**（4/8/16）|
| **批量提交** | ❌ | ❌ | **✅**（一次提 20 张工单）|
| **成本** | 订阅费 | 订阅费 | **自己的算力 + API**（可控）|
| **审计** | 依赖供应商 | 无 | **完整审计日志**（工单 → 交付 → 应用）|
| **交付物** | 直接改代码 | 直接改代码 | **冻结交付**（永久保存，可回溯）|

---

## 四大支柱

### 1. 自托管 + 隐私可控

**问题**：
- Devin 要把代码上传到云端
- 敏感项目（金融、医疗、政府）不能让代码出内网

**Lachesis**：
- 部署在你自己的机器或企业内网
- 代码不出公司
- 所有数据自己持有

---

### 2. Harness 中立 + 订阅池管理

**问题**：
- Codex 只能用 GPT
- Cursor 只能用 Cursor 自己的 harness
- 被供应商锁定，无法选择更好/更便宜的模型

**Lachesis**：
- 可插拔多个 harness（dsh、codex、claude-code、自定义）
- 可以自己写 adapter 接入公司内部模型
- 团队共享 API 订阅池（不用每人买一份）

---

### 3. 批量 + 并发 + 调度

**问题**：
- Cursor / Claude Code 一次只能跑 1 个任务
- 想修 20 个类似的 bug，要手动跑 20 次

**Lachesis**：
- 一次提交多张工单（批量）
- 并发执行（4/8/16，可配置）
- 智能调度（简单任务用便宜模型，复杂任务用强模型）
- 睡觉前提交 20 张工单，早上起来看结果

---

### 4. 交付冻结 + 可审计

**问题**：
- Cursor / Codex 直接改你的代码
- 改错了只能 undo / revert
- 没有审计记录

**Lachesis**：
- Agent 在独立工作区执行（不污染主项目）
- 交付物永久保存（所有改动可追溯）
- 调用方决定怎么处理（人验收 / 自动 apply / CI 集成）
- 完整审计日志（工单 → 执行 → 交付 → 应用）

---

## 目标用户

### ✅ 适合

1. **企业内网开发**
   - 代码不能上传到第三方
   - 需要内网部署
   - 需要完整审计日志

2. **团队协作**
   - 3-10 人团队，共享 Agent 机器
   - 共享 API 订阅池（省成本）
   - 批量提交工单，并发执行

3. **敏感项目**
   - 金融、医疗、政府
   - 需要审计、合规
   - 代码不能出公司

4. **成本敏感**
   - 自己的算力（不用付云服务订阅费）
   - 自选便宜模型（简单任务用 DeepSeek，复杂任务用 GPT）
   - 团队共享 API 额度

### ❌ 不适合

1. **个人开发者**
   - 用 Cursor / Claude Code 就够了
   - 不需要批量、并发、审计

2. **快速迭代项目**
   - 愿意「agent 改错了回滚就行」
   - 不需要审慎的验收流程

---

## 核心价值主张

**不是**：
- ❌ 多 agent 调度器（那是过度设计）
- ❌ 智能选 harness（那是高级功能，第一版不做）
- ❌ 自己的 harness（用现成的 dsh、codex 就够了）

**而是**：
- ✅ 企业级部署（自托管、内网、审计）
- ✅ Harness 中立（不被锁定、可插拔、可扩展）
- ✅ 批量并发（一次 20 张工单、并发执行、智能调度）
- ✅ 交付冻结（独立工作区、永久保存、可追溯）

---

## 与现有产品的对比

### vs Devin
- **Devin**：云端执行，代码上传到 Devin 云，订阅制
- **Lachesis**：自托管，代码不出内网，自己的算力和 API

### vs Cursor / Claude Code
- **Cursor/Claude Code**：单任务执行，直接改本地代码，固定 harness
- **Lachesis**：批量并发，独立工作区，可插拔 harness

### vs GitHub Copilot Workspace
- **Copilot Workspace**：云端，GitHub 生态，固定模型
- **Lachesis**：自托管，任意 git repo，任意模型

### vs agent-bridge
- **agent-bridge**：外部 CLI worker 的协调层（Grok Build、Kimi Code 等）
- **Lachesis**：工单系统 + 多 harness 调度，不依赖外部 worker

## 实现路线

### Week 1：单工单流程
- Issue CRUD
- 用 dsh 执行
- 返回交付物

### Week 2：并发 + Codex
- 调度器（并发 4）
- 加 Codex adapter
- 工单队列

### Week 3-4（可选）：
- HTTP API
- CLI 客户端
- 通知机制（webhook / 邮件）

---

## 最小系统验证标准

**成功标志**：
1. 能提交 3 张工单
2. 并发执行（2 张 dsh、1 张 codex）
3. 拿到 3 份交付物（改动的文件）
4. 调用方能自己决定怎么处理
5. 交付物永久保存，可审计

**如果这些都做到了，Lachesis 就有价值。**
