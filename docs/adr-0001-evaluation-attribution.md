# ADR 0001：工单评价与 Profile 归因

状态：采用，2026-09-24。依据施工包的已确认原则和 1–5 分建议规则，作为当前产品的明确量表；未来调整需要新 ADR 与迁移判断。

## 决定

操作者给一张工单评 1–5 整数分，可附文字意见。评分不是验收的必填项；未评分显示为空，不以 0 参与均值。失败工单可由操作者记录真实评价，无评分失败不自动给最低分。取消工单不允许评价。

每次评价记录工单、Run、可选交付、评价修订，以及 Run 冻结时的 Profile ID 和行为修订。Run 和交付是归因证据，评分对象仍是工单。每张工单可有多次评价，历史永久保留；只有最新有效评价进入当前聚合。一个工单在当前聚合中最多贡献一个样本，多次返工或并发实例不会倍增权重。

Profile 的每个行为修订分别计算已评工单的简单算术均值与样本数。只改名称或头像不创建新行为修订；改变供应商、模型或思考强度创建新修订，既有 Run 与评价仍指向旧修订。默认展示修订级履历，不能将跨修订均值当作当前模型能力。

## 边界

同一工单若由多个 Profile 分别尝试，评价明确指向选定 Run 的 Profile 修订，不自动复制给其他参与者。可选交付必须属于该 Run。复杂的多人共同交付与多维加权量表留待有实际场景时另行定义。

## 验证

Domain 测试覆盖未评分均值为空、同工单多次评价只取最新记录、跨行为修订归因，以及失败工单评价。评价与交付引用的一致性属于数据完整性检查。
