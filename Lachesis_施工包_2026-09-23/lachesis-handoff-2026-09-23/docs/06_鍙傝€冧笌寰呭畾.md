# 06 · 参考与待定

## 1. 今天调研的项目如何使用

本章保留设计借鉴，不重新评测这些项目，也不把前文对主分支的观察当成今后的版本保证。施工前只核对实际依赖所需的接口；不要因为归档了这些项目，就同时引入它们的服务与数据库。

| 项目 | 保留的参考价值 | 当前决策 |
|---|---|---|
| OpenAI Symphony | 工单资格检查、工作区生命周期、重试、状态校对、仓库内工作流政策 | 读规范，不把其现有执行服务当作必须依赖 |
| Paperclip | 工单／Run 分离、领取、持久执行记录、验收与反馈 | 不采用完整自治公司模型作为 MVP 基座 |
| Vibe Kanban | executor／profile 变体、工作区、差异审查、外部调用体验 | 借鉴执行与审查界面，不绑定其托管服务 |
| Pi | SDK 嵌入与可替换运行时边界 | 保留为后续候选，第一版不切换 |
| dsh | 插件式运行时、会话、工具循环、执行配置与接入路径 | 第一阶段唯一运行时；必须固定版本做契约验证 |

前文讨论了项目维护变化、试验性模块和草案。它们不是本项目冻结需求；未在此归档操作中重新运行、压力测试或验证所有主分支能力。计划文档与已发布实现需要在施工时分开对待。

## 3. 尚未拍板的事项

| 事项 | 建议处理 |
|---|---|
| 仓库名、域名 | 产品名已定为 **Lachesis**；仓库建议 `lachesis` 或可用变体，域名可用性另行确认 |
| dsh 精确版本和接口路径 | M0 实测后固定 |
| worker 同进程还是独立进程 | 以隔离、取消与成本的实际测试决定 |
| 数据库和 UI 技术细节 | 先选能复用 dsh 且简单可测的方案 |
| 默认自动路由策略 | 先实现显式指定，再加一个简单策略 |
| 1–5 分、评分维度、权重 | 第一版建议单分＋意见＋简单均值，须记录决策 |
| 多 Profile 联合工单如何归因 | 不自动复制评分；先明确主执行配置或拆工单 |
| 模型／强度变更后的跨版本聚合 | 建议保留修订并分开展示，具体规则写入 ADR |
| 账号额度获取和精确成本 | 只支持真实可取得信息；未知就保留未知 |
| 头像批量生成与管理 | 后续再做；第一版绑定静态素材 |
| GitHub／Linear 等外部工单同步 | 后续入口扩展，不是现阶段数据库选择 |
| Consult 等其他协作模式 | 可复用配置与执行能力，但不是本次 MVP 新增目标 |

## 4. 不应从旧图或旧例子继承的默认值

不要默认使用某个过时模型；不要把供应商品牌等同一个账号；不要把 high／medium／low 当作所有模型的合法参数；不要把图中人名当真实用户；不要写入虚构评分历史；不要默认拥有原头像的发布权；不要声称已有商业部署或代码成果。

## 5. 下一步原则

能够安全默认的实现细节写 ADR 后推进；涉及产品边界、评分归因或真实权限变化的决定，应明确记录而不是隐藏在代码里。保留一个薄执行接口，避免为未来假想的十种 CLI 建设通用平台。
